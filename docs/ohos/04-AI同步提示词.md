# AI 同步提示词

> 适用：把主线 `mtbbs` 的最新代码（**含上游未提交的工作区内容**）同步进鸿蒙独立版。
> 使用方式：把下面整段提示词复制给 AI，并告诉它仓库路径。
>
> 前置：**本仓库工作区必须干净（已提交）**。上游不要求干净——上游工作区当前内容就是同步源。

规则细节全部在 [03-同步上游.md](./03-同步上游.md)，下面的提示词只负责"把 AI 按到那份规则上"。

## 提示词（复制整段）

````text
你是 mtbbs 鸿蒙独立版的同步工程师。仓库：C:\files\project\flutter\mtbbs_app_ohos，
上游主线工作区：C:\files\project\flutter\mtbbs。

先做一件事：完整阅读 docs/ohos/03-同步上游.md，并把它当作唯一规则来源。
本文只是最低约束；03 与本提示词冲突时，以 03 为准，并在汇报里指出冲突点。

背景：
- 本仓库是 https://github.com/qcxs/mtbbs_app.git 的鸿蒙独立版，只用 Flutter-OH SDK 构建。
- 同步方式是**文件级镜像**（robocopy /MIR + 排除清单），**不用 git merge / cherry-pick**。
  git 只用于：看上游改了什么（log/diff/show）、确认下游干净（status）、比对内容（diff --no-index）。
- lib/ 的上游文件必须与上游完全一致；鸿蒙专属 Dart 代码只允许写在 lib/ohos/。
  此外的鸿蒙特有内容只有 ohos/、docs/ohos/ 与 pubspec.yaml 末尾的 dependency_overrides 段。
- 本项目用 fvm 固定 SDK（.fvmrc = flutter_ohos/oh-3.44.9-dev），
  所有 Flutter 命令一律 `fvm flutter`，禁止用全局 flutter、禁止用官方 Flutter 构建本仓库。
- 功能分流：与鸿蒙无关的通用功能应由主线实现，下游只做平台适配，不新增特性。

任务：
把上游工作区的最新文件镜像进本仓库，完成 4 个混合文件的手工合并，跑完验证清单，
并按 03 第 8 节模板汇报。

开工前（任一命中就停，不要 stash/reset/临场发挥）：
1. 下游 `git -C C:\files\project\flutter\mtbbs_app_ohos status --short` 非空（含未跟踪文件）。
2. 当前分支不是 main（或我指定的分支）。
3. 下游 lib/（排除 lib/ohos）里有上游不存在的下游改动（说明有人手改了上游文件）。
4. 镜像目标目录不可写 / robocopy 报 Access denied。

执行（顺序固定）：
1. 只读取上游改了什么（供汇报，不参与合并）：
   `git -C C:\files\project\flutter\mtbbs log --oneline -10`
   `git -C C:\files\project\flutter\mtbbs status --short`
   `git -C C:\files\project\flutter\mtbbs diff --stat HEAD~3..HEAD`
2. 集合侦察（预期无输出）：
   上游 lib 与下游 lib（排除 ohos）的文件集合差异 = 0；docs 同理。
3. 镜像（/MIR = 覆盖 + 删除上游已不存在的文件）：
   `robocopy <上游>\lib    <下游>\lib    /MIR /XD <下游>\lib\ohos`
   `robocopy <上游>\assets <下游>\assets /MIR`
   `robocopy <上游>\test   <下游>\test   /MIR`
   `robocopy <上游>\tool   <下游>\tool   /MIR`
   `robocopy <上游>\docs   <下游>\docs   /MIR /XD <下游>\docs\ohos /XF "15-版本发布.md"`
   robocopy 退出码 0/1/3 都算成功，>=8 失败；失败先原样重跑一次。
4. 手工合并 4 个混合文件（03 第 4.2、4.3 节）：
   - pubspec.yaml：以上游为底，末尾追加下游 dependency_overrides 整段
   - AGENTS.md：以上游为底，补回鸿蒙段落与 docs/ohos 路由，删除 docs/15 行；
     上游铁律/路由表的新增行必须全量吸收
   - README.md：以上游为底，补回鸿蒙构建章节与 docs/ohos 子树；
     上游功能表/文档树的新增行必须全量吸收；平台措辞保留下游版本
   - .gitignore / .metadata：保留下游版本（上游新增非平台忽略项时才吸收）
5. 兜底清理（镜像已排除，只防止平台目录被带入）：
   `git -C <下游> rm -r --ignore-unmatch android windows installer .github ios macos linux`
6. 依赖：若上游升级 path_provider / url_launcher / flutter_inappwebview / file_picker，
   先确认 OH fork 有对应分支；有则只更新 dependency_overrides 的 ref，没有则保持旧 fork 并记录差异。
   上游新增可选插件：有 OH 实现不动；没有就停下，说明需要上游 AppCapabilities 关闭该能力。
7. 验证（逐条跑，结果原样贴汇报）：
   `fvm flutter pub get`
   `fvm flutter analyze lib`
   robocopy /L 预览（lib、docs、assets、test、tool）——必须无输出
   `git -C <下游> status --short -- lib ':!lib/ohos'`   # 必须为空
   `(Get-Content .flutter-plugins-dependencies -Raw | ConvertFrom-Json).plugins.ohos.name`  # 5 个插件
   `fvm flutter build hap --debug   --target-platform ohos-x64`
   `fvm flutter build hap --release --target-platform ohos-arm64 --no-codesign`
   构建失败先原样重跑一次；仍失败再分析（已知竞态见 docs/ohos/01 第 5 节）。
8. 在 03 第 9.1 节追加本次同步记录（日期 / 上游 HEAD / 上游未提交文件数 / 覆盖范围）。

汇报：按 docs/ohos/03-同步上游.md 第 8 节的模板输出，不要省略任何一项。

禁止：
- 不要用 `git merge` / `git cherry-pick` / `git rebase` 来同步。
- 不要使用全局 flutter；不要用官方 Flutter 构建本仓库。
- 不要删除或清空 dependency_overrides 段；不要改上游 dependencies 的版本号。
- 不要为了让构建/分析通过而改 `lib/` 的上游文件（`lib/ohos/`、`ohos/` 除外）；
  需要改就先停下来告诉我（要么放下游专属目录，要么上游化）。
- 不要提交或推送，除非我明确说"提交/推送"。
- 不要用 `git reset --hard`，除非我明确要求。

已知坑：
- `.plugin_symlinks\file_picker` 符号链接错误：原样重跑一次。
- `hvigor ERROR ... undefined (reading 'filter')`：重跑 `fvm flutter pub get`，
  并确认 `.flutter-plugins-dependencies` 有 ohos 段。
- robocopy 中途 Access denied：文件被编辑器/杀毒占用，原样重跑一次。
- release 首次偶发失败：原样重跑一次。
- `--no-codesign` 产物不能安装；签名不在同步范围内。

失败回滚：
- 未提交：`git -C <下游> checkout -- .` + `git -C <下游> clean -fd lib assets test tool docs`（不要加 -x）
- 已提交但验证失败：停下来告诉我，由我决定是否 revert；不要自行 reset。
````

## 附：给鸿蒙仓库加特有功能时，改哪个仓库？

AI 接到"给鸿蒙加某个功能"时，先按这张表定位，**默认不要改 `lib/` 的上游文件**：

| 需求形态 | 改哪里 | 理由 |
|---|---|---|
| 纯原生能力（通知、权限、窗口、系统 API、原生插件） | 本仓库 `ohos/`（+ `docs/ohos/`） | 上游没有该目录，天然零冲突 |
| 需要 Dart 侧配合（新页面、新逻辑、新开关） | 本仓库 `lib/ohos/`；需要「随 App 自动注册」的 Dart 插件写 `packages/`（现有 `mtbbs_ohos_bridge`），构建不用 `--target` | 上游永不存在这些目录，同步零冲突；改了上游 `lib/` 的其它文件，上游大重构时会持续制造差异 |
| 需要判断当前平台 | 在 `lib/ohos/` 内用 `Platform.operatingSystem == 'ohos'` 或 `defaultTargetPlatform.name` 字符串判断 | 官方 Flutter 没有 `TargetPlatform.ohos`，直接引用会让上游 Android/Windows 编译失败；判断代码因此只能放在下游专属目录 |
| 平台能力有无 | 上游 `lib/core/app/app_capabilities.dart` 的能力开关（仅当**两个仓库都需要**这件能力时） | 鸿蒙缺插件时统一降级；只对鸿蒙有意义的开关，放 `lib/ohos/` |
| 依赖差异 | 本仓库 `pubspec.yaml` 的 `dependency_overrides` | 属于本仓库自有配置 |

判断口诀：**能只写 `ohos/` 就只写 `ohos/`；需要 Dart 就写 `lib/ohos/`；需要自动注册的 Dart 插件写 `packages/`；只有"上游也该有"的通用能力才上游化。**

`lib/ohos/` 内可以自由 import `package:mtbbs/...` 的上游文件；上游重构导致 import 失效时，`flutter analyze lib` 会直接报错，按 03 文档修 `lib/ohos/` 即可，不需要动上游。
